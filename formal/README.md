## 目的

本ファイルは、パスキーゲートウェイの Caddy ルーティング挙動を Lean で形式化するにあたり、
形式化の範囲・使用する変数と命題・検証手順・未確認点・スコープ外を記録する。
`status: draft` であり、モデルが実際の Caddy / oauth2-proxy の挙動と一致することを主張しない。
実ホスト名・トークン値は記載せず、`<expected-host>` 等のプレースホルダに限定する。

## 変数と命題

### 変数

- `H`: Host ヘッダが期待値 `<expected-host>` に一致すること。
- `O`: パスが `/oauth2/*` 配下であること（認証フロー自身は `forward_auth` を通らない）。
- `A`: `forward_auth` のサブリクエスト応答が 401 以外であること。属性ヘッダは認証結果の産物であり、判定条件ではない。
- `T`: パスが `/trial*` 配下であること（`:18888` のみ必須）。
- `g`: 評価対象のゲートを指す添字（扱いは未確認）。
- `R400`: HTTP 400 応答を返すこと。
- `R302`: HTTP 302 リダイレクトを返すこと。
- `U`: アップストリームへプロキシすること。

### 命題

- 命題1: `¬H → R400`（期待 Host でなければ 400 を返す）。
- 命題2: `H ∧ ¬O ∧ ¬A → R302`（期待 Host かつ `/oauth2/*` 以外かつ認証応答が 401 なら 302 を返す）。
- 命題3: `H ∧ A ∧ ¬O ∧ T → U`（期待 Host かつ認証済みかつ `/oauth2/*` 以外かつ `/trial*` 配下なら
  `:18888` へプロキシする。`T` は `:18888` のみで必須、他ゲートは `T` を要求しない）。

これらは記号真理値上の含意であり、Caddy の実意味論を証明したものではない。

## 検証手順

実際の検証は親エージェントが実行する。子は以下のコマンドを提案するのみで、実行しない。

```bash
bash scripts/check-lean.sh
```

- `lake build --wfail CaddyFormal`: 警告をエラーとして扱い、明示ターゲットをビルドする。
- olean 存在確認: ビルド成果物（`.lake/build/lib/lean/CaddyFormal.olean` と
  `Caddy.olean`）が無い場合はゲートを失敗させる。
- `lake env leanchecker Caddy`: 証明本体を含むモジュールを直接再検査し、未解決の
  公理や `sorry` の有無を確認する。olean 不在時は明示的に失敗させる。

スクリプトが非ゼロを返さない場合に限り、形式化の健全性を確認したとみなす。
検証対象は手書きの Bool モデルであり、実 Caddyfile の意味論ではない点に注意する。
